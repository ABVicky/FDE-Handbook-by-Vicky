# Exercise 04 — Spot the bad problem statement

*This module's "break & fix" challenge.*

A good problem statement answers: **Who** has the problem? **What** is it, concretely? **How much** does it cost now? **How will we know** it's solved? And it doesn't name a solution.

Each statement below is broken. For each one: (1) name what's wrong, (2) list the questions you'd ask the client, (3) rewrite it. You may invent plausible numbers, but mark them as assumptions.

1. "We need an AI chatbot for our website."
2. "Our processes are inefficient and we want to digitally transform operations."
3. "Customer support is slow."
4. "Build a dashboard showing all the data from our CRM, ERP, finance system and HR system so management can make better decisions."
5. "Reduce invoice processing time by using machine learning to extract invoice fields with 99.9% accuracy by next month."

## A template for your rewrites

> **[Who]** currently **[does what / experiences what]**, which causes **[measurable cost: time, money, errors, lost customers]**. Today the baseline is **[number]**. We'll consider this solved when **[metric]** reaches **[target]** by **[date]**, without **[constraint, e.g. extra staff, data leaving the country]**.
