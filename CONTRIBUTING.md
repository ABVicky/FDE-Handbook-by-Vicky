# Contributing

Thank you for helping build the FDE Handbook by Vicky.

## Ways to contribute

| Contribution | Where | Notes |
| --- | --- | --- |
| Fix a typo, broken link or error | Anywhere | Small PRs welcome, no issue needed |
| Write a lesson or module | `modules/` | Open an issue first so work isn't duplicated; use [the module template](templates/module-template.md) |
| Add a sourced case study | `case-studies/` | Must cite a public source with link and date |
| Add a job description snapshot | `resources/job-descriptions/` | Public postings only; name `YYYY-MM-company-title.md` |
| Add a template or worked example | `templates/` | Include both blank and completed versions |
| Add a resource link | `modules/*/resources.md` or `resources/` | Official docs first; one line on why it's worth reading |
| Request peer review of your work | Issues → "Peer review" label | Link to your fork and the module's "Done when" list |

## Quality bar for lessons

- [ ] Starts with *why* it matters to an FDE, ideally through AdmitFlow
- [ ] Explains what it is, why it exists, how it works, where it's used, and its limitations
- [ ] Includes a diagram where it helps (Mermaid preferred, so GitHub renders it)
- [ ] Code runs as written, with pinned versions
- [ ] Links to official documentation first
- [ ] Ends with a "Check yourself" question
- [ ] Read by at least one person who doesn't already know the topic

## Writing style

- Plain, direct English. Short sentences. Explain jargon the first time you use it.
- Address the learner as "you."
- Mark content as **Core** or **Stretch**.
- Label illustrative examples clearly; never present invented stories or numbers as real.
- Add a `Last verified: YYYY-MM-DD` line to tool-specific lessons.
