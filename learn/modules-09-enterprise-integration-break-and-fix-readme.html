Module 09 — Break & Fix: 240 contacts for 99 students

Time: 1–2 hours · Do this after Lesson 04.

The situation

The marketing team syncs AdmitFlow leads into their CRM every night, using a script a contractor wrote: naive_crm_sync.py. Its selling point: "Robust: retries on any network error!"

After a week, marketing complains: students are receiving the same newsletter three or four times, and the CRM's contact count is far higher than the number of enquiries.

The CRM is simulated by flaky_crm.py: it behaves like a real API on a real network, where occasionally a request succeeds on the server but the response is lost.

cd modules/09-enterprise-integration/break-and-fix
python naive_crm_sync.py
leads with email: 99
contacts in CRM:  240
duplicates:       141

Your job

  1. Explain both ways this script creates duplicates. (There are two separate mechanisms.)
  2. Fix it so that any number of runs, with any number of lost responses, ends with exactly one contact per student.
  3. Prove it with a test against FlakyCrm.
  4. Write a short plan for cleaning up the existing duplicates in marketing's CRM, safely.

Hints

Hint 1What happens on the CRM side when create_contact retries after a ReadTimeout?
Hint 2What does the script remember between nightly runs? How does run 2 know a student was already synced?
Hint 3Before creating, what could you ask the CRM? After creating, what must you save, and where?
