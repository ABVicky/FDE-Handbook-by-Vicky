Exercise 04 — Model review

Overall: Request changes. The idea is useful, but this endpoint exposes every student's contact details to anyone on the internet.

#SeverityIssueWhy it mattersSuggested fix
1🔴 CriticalNo authentication: no current_user dependencyAnyone who finds /export downloads all names, phones and emails, which is a data-protection breachAdd Depends(require_admin) (the director/admin only), plus a test that it returns 401/403
2🔴 HighPersonal data printed to stdout (print("exported", rows))Logs are kept, copied and shared; now they contain every student's contact detailsRemove it. If needed, log exported %d leads with the count only
3🟠 HighHand-built CSVNames like "Lee, Chloe" or with quotes break the columns; values starting with =, +, -, @ can execute as formulas in Excel (CSV injection)Use csv.writer (or the existing store.export_csv), and prefix risky leading characters with '
4🟠 MediumSilently truncated to 100 leads (limit=100)The director gets a partial file and thinks it's completeExport everything (stream it if large), or paginate explicitly and say so
5🟡 MediumNone written as the text NoneSpreadsheet shows "None" for missing phonesWrite empty strings for missing values
6🟡 MediumNo Content-Disposition header; not UTF-8 BOMBrowser may display rather than download; Excel garbles NguyễnContent-Disposition: attachment; filename="leads.csv", encode utf-8-sig
7🟡 LowString concatenation in a loopQuadratic-ish for big exportscsv.writer into io.StringIO, or a StreamingResponse
8⚪ ProcessNo tests, vague descriptionReviewers can't tell what was checkedTests for auth, quoting, full export; description with what/why/how tested

Comment to the author (tone matters):

Thanks, the director will love this. Before merging, could we lock it to admins and drop the print? Right now it would expose all student contacts publicly. I'd also suggest reusing store.export_csv, which already handles quoting and Excel encoding. Happy to pair on the tests if useful.
