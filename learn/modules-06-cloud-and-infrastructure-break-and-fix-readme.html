Module 06 — Break & Fix: "Works on my laptop"

Time: 1–2 hours · Do this after Lesson 04 and Lesson 07.

The situation

Another engineer deployed AdmitFlow to the institute's office VM (10.20.0.15) before going on leave. You've been handed:

  • handover/docker-compose.yml
  • handover/notes-from-previous-engineer.md
  • logs from four attempts to get it working: logs-api.txt, logs-curl.txt, logs-browser.txt

Mr. Fernandes: "Counsellors can't log in. The pilot starts Monday."

The logs are illustrative but realistic. You don't need Docker to do this exercise: diagnosing from configuration and logs, without direct access, is exactly what FDEs often have to do. (If you have Docker, reproduce it for extra credit.)

Your job

There are four separate configuration problems, each of which hides the next one. For each:

#Symptom (quote the log line)Root causeFix (exact change)How to stop it happening again

Then:

  1. Write the corrected docker-compose.yml.
  2. Write a short go-live checklist that would have caught all four before Monday.
  3. Write a 5-line message to Mr. Fernandes: what was wrong (no jargon), what's fixed, and when counsellors can log in.

Hints

Hint 1Inside a container, 127.0.0.1 means the container itself. Which address must a server listen on so that traffic forwarded from outside the container can reach it?
Hint 2The same rule applies to DATABASE_URL. In Compose, how does one service reach another?
Hint 3The browser's origin is http://10.20.0.15:8080. Compare it, character for character, with ADMITFLOW_CORS_ORIGINS.
Hint 4Read the last error. Which required variable does the Compose file never set? Where should its value come from?

When you're done: SOLUTION.md
