Glossary

Terms used across the handbook, with the module where each is taught.

TermMeaningModule
Acceptance criteriaTestable conditions a feature must meet to be "done" (Given / When / Then)04, 11
ADRArchitecture Decision Record: a short note of a decision, its context, consequences and alternatives04
AgentA loop where a model chooses the next action (often tool calls) until a task is done08
APIApplication Programming Interface: a defined way for programs to talk to each other, often over HTTP02, 04
Audit logAppend-only record of who did what, when10
AUC (ROC AUC)How well a model ranks positives above negatives (0.5 random, 1.0 perfect)07
BackoffWaiting longer between each retry (1, 2, 4… seconds)03, 09
BaselineA simple comparison point: today's metric, or a trivial model01, 07
BM25A keyword-search ranking algorithm weighting rare terms08
ChunkA piece of a document indexed for retrieval (AdmitFlow: one section)08
CI/CDContinuous integration (test every change) / continuous delivery (ship every change safely)06
Circuit breakerStops calling a failing dependency for a while, failing fast instead10
Container / imageA packaged application and its dependencies / a running instance of it06
CORSBrowser rule that blocks cross-origin requests unless the server allows them04
Data contractAn agreement on the format, meaning and delivery of data between two teams05
DedupeFinding and merging records about the same thing03
DiscoveryUnderstanding a client's problem before designing a solution01, 11
EmbeddingA vector representing meaning, so similar texts are close together07, 08
Entity resolutionMatching records about the same real-world entity across systems05
Error budgetThe amount of failure an SLO allows10
ETL / ELTExtract-transform-load / extract-load-transform05
Evaluation setTest cases with expected results, used to measure an AI feature07, 08
Field TrackThis handbook's client-facing exercise in every moduleall
GroundingMaking an AI answer come only from provided sources, with citations08
HallucinationFluent, confident output that isn't supported by facts08
HMACA keyed hash used to sign messages (e.g. webhooks)09
IdempotentRunning an operation twice has the same effect as once04, 05, 09
Index (database)A structure that makes lookups fast05
JWTJSON Web Token: a signed token carrying claims (who, role, expiry)04
LeakageUsing information during training that won't exist at prediction time07
Least privilegeGiving each user, service and tool only the access it needs06, 10
MCPModel Context Protocol: an open standard for exposing tools and data to AI applications08, 09
MigrationA versioned script that changes a database schema05
N+1 problemRunning one query per item instead of one for all05
OIDCOpenID Connect: an identity layer on OAuth 2.0 (sign-in, ID tokens)09
Outbox patternRecord intended side effects in your database; a worker delivers them09
PIIPersonally identifiable information05, 10
Precision / recallOf items flagged, how many were right / of right items, how many were flagged07
Prompt injectionText in the model's input that tries to override its instructions08, 10
RAGRetrieval-augmented generation: retrieve relevant documents, answer from them08
Rate limitingRestricting how often a client can call an endpoint10
Readiness / liveness"Can it serve now?" / "Is the process alive?" health checks06
Repository (pattern)Data access behind an interface, so storage can change04
RPO / RTOMaximum acceptable data loss / downtime10
RunbookStep-by-step operating procedures and alert responses10
SLI / SLOA measurement of user experience / the target for it10
SSOSingle sign-on with an organization's identity provider09
Structured outputA model reply constrained to a JSON schema08
System of recordThe authoritative source for a type of data09
Threat modelA structured look at how a system could be attacked, and the controls10
WebhookAn HTTP request a system sends you when something happens09
